# Phase 41 - The Third Full Security Audit (and the First to Cross Three Servers)

Every previous audit looked at one growing app on one or two servers. This one didn't have that
luxury — it's the first pass since Licensing shipped, which means it's the first pass that has to
look at three separate live servers and three separate repos at once, one of which (the licence
server) had never been audited at all before today, and one of which now handles real payment
webhooks from a real payment processor.

Two things needed fixing, both in the newest and least-scrutinized code.

**The bigger one**: the "one license, one server" check — the thing that's supposed to stop a
single paid license from running on an unlimited number of real installs — compared the license's
stored IP against an IP the *client* reported about itself, not anything actually observed about
the connection. That's backwards. A license key, once known, could be run anywhere, on as many
servers as someone wanted, just by having each install claim whatever IP the license was already
bound to. The fix uses the real TCP peer address the web server handed to PHP instead — the one
number a caller can't just decide to lie about.

The smaller one: two brand-new public endpoints (`/validate`, the license check every install runs
hourly, and `/trial`, which mints a real 30-day license key on request) had no rate limiting at
all. License keys carry enough entropy that brute-forcing one isn't a realistic worry, but nothing
was stopping a script from farming free trial keys indefinitely. Both endpoints are throttled now
— generous for anything a real install would ever do, a real brake on anything scripted.

Everything else new got the same scrutiny and came back clean: the Lemon Squeezy webhook is
signature-verified with a constant-time comparison and fails closed if the secret's ever unset —
confirmed that's not a theoretical claim by checking the live server actually has it configured,
not left in the "no real store exists yet" state the code was written against. Cron Jobs, the
subsystem with the most obvious way to go wrong (it installs real crontab entries, and a crontab
line is one newline away from becoming two), turned out to have every layer already in place:
anchored field validation, execution as the account's own user, and the root provisioning script
independently re-checking everything rather than trusting the app that called it — the same
"never trust the caller" rule every privileged action in this app has followed since the very
first audit. The backup engine's restore path, the one place a wrong assumption about a filename
could turn into reading or writing outside where it should, computes every downloadable filename
from a manifest stored at backup time, never from anything a request supplies — there's no string
to traverse with.

One deliberate design question got re-examined rather than just re-read: does a lapsed license
lock KNJ Webmail along with everything else? It doesn't — and checking that this was actually
correct rather than accidental mattered, because it's easy to read that as a gap. It isn't one.
Webmail is how a customer reads mail that already exists on the mail server regardless of what
KNJ Panel's own license status is — exactly the category of thing Tier 2's whole design already
promised would never be touched by a licensing problem that's the *operator's* problem, not
theirs. It stayed out of the enforcement gate for the same reason SSL renewal and cron jobs do.

The honest one, filed as an outstanding note rather than a fix: a customer running this on their
own server can, with root access they already have, edit the license flag in their own database
directly. There's no code fix for that — it's the same limitation every piece of self-hosted
licensed software has always had, and the only lever that actually holds regardless is server-side
revocation, which nothing local can touch.

All four repos' full git history got scanned for anything that should never have been committed —
including the license server's, for the first time, its entire 16-commit lifetime. Nothing found,
anywhere, ever. Live state on all three servers reverified against `HEAD`, not assumed from the
last deploy; all three test suites green.
