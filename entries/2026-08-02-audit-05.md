# Phase 45 - The Fourth Full Security Audit (and Two Scripts That Modified Themselves)

This one started as a small, deliberate safety net — a fresh install had just proven the release
pipeline works end to end, and it seemed worth adding one more guard: the install script should
refuse to run somewhere it could genuinely damage a real, in-progress checkout. That single guard
turned into a genuine debugging chase, and the whole thing ended in a full audit.

The guard itself was simple: detect a live source-control checkout and refuse to run against it,
rather than silently deleting files that don't belong in a packaged release. Adding the check was
the easy part. Proving it actually worked was not — the first real test against a live, protected
box did the exact damage the guard was supposed to prevent, because the fix had landed in the
source but not in the copy that was actually running. Two completely separate scripts turned out
to have the same underlying problem: each one tried to keep its own installed copy in sync with
itself while it was the one currently executing. One did it quietly and just didn't take effect;
the other crashed outright with a real syntax error the moment its own content changed enough to
trigger it. Both are now installed as a tiny, permanent stub that always runs the current version
fresh — nothing is ever asked to update itself while running, for either script, ever again.

Along the way, a second, unrelated problem surfaced: one of these same scripts had quietly been
stripping the one set of dependencies needed to run tests at all, on every single automatic deploy,
which meant "run the test suite" kept silently breaking within minutes of being fixed by hand.
Also fixed, verified with a full clean pass afterward.

None of this touched anything a real customer install depends on — every fix here is either
dev-only tooling or defense that was always meant to exist and simply wasn't being exercised for
real until today. But between the trial-licence fix from earlier this week (confirmed live, for
real, on a genuine reinstall — same trial resumes with days remaining, or locks cleanly to "buy a
licence" if it's actually expired) and this pass, it felt like the right moment for a proper audit
rather than moving straight on.

The audit covered everything shipped since the last one: the full release pipeline now that it's
actually been exercised for real, the self-service profile changes, and a fresh look at the
privilege boundary the panel's own update mechanism runs through. That last one turned up a real,
if narrow, gap — a system permission was scoped more loosely than it needed to be, in a way that
would only matter if the application itself were already compromised, but that's exactly the kind
of boundary that's supposed to hold regardless. Tightened and verified: the legitimate path still
works exactly as before; the loophole is now closed and confirmed closed, not just assumed closed.

Every historical release ever published was checked directly, not just the process that builds
them — nine releases, zero leaks. Git history across every repository with activity since the last
audit came back clean. All three application test suites are green, and all four live servers now
in the estate — including the disposable test box added this week — were checked directly rather
than trusted from memory: correct code, correct version, correct running state, nothing left over
that shouldn't be there.
