# Phase 50 - The Fifth Full Security Audit (and a Live Symlink Escape)

With the Security section closed out, it felt like the right moment for another full pass — 26
commits since the last one, spanning Access Control, Password Policy, API Tokens, the whole Service
Configuration section, and the Accounts batch. Two of the findings this time were real, not
theoretical.

The bigger one: WebDAV's directory scoping only got checked once, at the moment a credential was
created. The web server regenerates that boundary fresh on every single request afterward, and
nothing was stopping an account owner from deleting the directory they'd been scoped to and
replacing it with a symlink pointing somewhere else entirely — another customer's files, or the
backup store. No further action needed on our side; the web server would just follow the link the
next time anyone touched that WebDAV path. Closed with the standard safeguard for exactly this
class of bug, and a test now proves every generated config carries it.

The other real one: a broadcast message to every account owner on the server was supposed to queue
as a background job, one email at a time, so it could never hold up the request that sent it. It
never actually did — a one-line interface was missing, so every send happened synchronously, inline,
during the admin's own click. On a small account list you'd probably never notice. On a big one,
the request would likely time out partway through with no record of who got missed. Fixed, and
guarded with a test that checks the interface directly, since the usual way of testing notifications
doesn't actually exercise whether something queues or not.

Three smaller things closed alongside those: a bulk-removal action was letting one server role infer
whether an account ID existed anywhere on the server, purely from a response code; two settings
reaching the privileged provisioning layer weren't independently re-checked the way every sibling
setting already is; and the new API surface had no rate limit at all, unlike every other login-
adjacent endpoint in the panel. All narrow, all closed the same day, none require any customer
action.

One more thing surfaced along the way that wasn't a security issue but was worth fixing regardless:
the CI test workflow had quietly been failing on every single push since Aug 3, over two small style
violations in files this session never directly touched. Every local style check run used a "just
the files I changed" mode, which never caught it — a full, undirty pass across the whole repo found
and fixed both in seconds once actually run.

Everything else checked out clean: the new firewall allow-lists, the central password policy, and
every ability check on the new scoped API tokens, confirmed live with real tokens against a real
server. Git history across every repository with activity since the last audit came back clean,
including a session that involved genuine SSH access and real minted tokens. All three servers now
in the estate checked directly — code, version, and running state all matching what was actually
deployed, full test suites green on each.
