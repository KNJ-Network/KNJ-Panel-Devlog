# Phase 116 - Line-By-Line Bug Sweep: Correctness, Not Security

Last piece of today's plan, and deliberately a different lens from the three audits that ran earlier —
those covered auth, injection, and authorization; this pass hunted for plain correctness bugs across
the same window (everything shipped since Audit #11, 2026-08-17): logic errors, state-management gaps,
silent failures, off-by-ones. Five parallel passes — controllers, services, views, models/jobs/commands,
and the provisioning script — each independently verified against the actual code, same discipline as
every other review today.

## What actually broke things

**Switching the active Mail Only server never re-applied Dovecot config.** `MailSettingsController::
updateServer()` resynced mailboxes, catch-alls, mailing lists, and forwarders on switch, but never
called `MailServerConfigService::apply()` — the one thing that pushes the Sieve plugin config Dovecot
needs. Any install that had ever touched an autoresponder, mail filter, or spam threshold before linking
a Mail Only server (the ordinary case) would switch to that server and have every one of those features
silently do nothing on it, with no error anywhere. Fixed by adding the missing call, same fix pattern
the other four resyncs already used.

**Deleting the active Mail Only server left a dangling pointer.** `ServerController::destroy()` deleted
the row with no check for whether it was the currently active mail server, and never cleared
`mail.active_server_id`. Every mail-touching service already correctly stopped dispatching remotely once
the pointer resolved to nothing — but they only ever checked "is a value present," not "does it still
point at something real," so every mail action would have quietly started running against Main again
instead of erroring, while the Mail Settings page kept showing the deleted server as active.

**The exact DNS-only licensing bug, reintroduced for Mail Only.** `ValidateLicense`, the command that
runs hourly, only ever checked `ServerRole::DnsOnly` in its exemption — the same gap `LicenceController`
had (fixed earlier today in audit #14), just in the scheduled job instead of the web routes. A Mail Only
box would have kept requesting an unwanted trial licence every hour, indefinitely — the identical
incident that already happened once to a DNS-only test box.

**BIND9 and vsftpd showed permanently "Inactive" on Mail Only, once a domain was set.** Same root cause
as the DNS-only fix from two audits ago, just never carried over to the newer role: neither unit is ever
installed on a Mail Only box, but only `dns_only`'s exclusion list dropped them from the status page and
dashboard card. Before a domain was configured both correctly read "not set up yet"; the moment one was,
they flipped to a red "Inactive" that would never clear, since neither unit is ever actually there to
become active.

**An addon-domain limit that didn't match what the page told the customer.** `DomainsController::store()`
counted subdomains toward the addon domain limit; `index()`'s displayed count didn't. An account with
several subdomains — which the page itself says don't count — could get blocked from adding a real addon
domain earlier than it was told it would be.

## Smaller fixes

- A check-then-create race in `GitDeployController::deployNow()` — two near-simultaneous submits could
  both pass the "already running" check before either committed, queuing two deploys against the same
  working directory. Wrapped in a `Cache::lock()`, the same fix pattern used for the setup wizard's
  admin-creation race two audits ago.
- `User::terms_accepted_at` was never added to `$casts()` — a latent gap, not yet triggering anything,
  but the moment any code formats it as a date it would have failed.
- `DnsSecondaryZoneStatusService` swallowed a failed provisioning-script call completely silently,
  returning an empty zone list indistinguishable from a genuinely empty install. Now logs a warning
  instead — kept as a soft failure rather than an exception, since this feeds a dashboard card, and a
  500 there would be worse than a stale reading.
- Two bugs in the provisioning script's DNS-only secondary-zone actions: a `grep -c` count could
  concatenate with its own `|| echo` fallback on a genuinely-zero result, corrupting the one-line-per-zone
  status format; and the zone-list write loop was missing the `read -r LINE || [[ -n "$LINE" ]]` guard
  this exact diff added four other places for the same reason, which would silently drop the last domain
  in the list if it ever arrived without a trailing newline. Neither is reachable through the current
  real caller — both closed anyway, same discipline as every Low-severity defense-in-depth fix in
  today's audits.

## What's flagged, not fixed

- **Mail Only's own dashboard shows Accounts/Packages/Resellers/Servers cards that all 404 when
  clicked** — the same gap DNS Only had before it got a dedicated dashboard view. Needs the equivalent
  build, not a quick patch; noted for a future pass rather than rushed today.
- **The hardware fingerprint used to prevent trial-licence abuse no longer survives an OS reinstall.**
  The fix that resolved a real sudo-hang bug switched from the SMBIOS UUID to `/etc/machine-id` — which
  the code's own docblock still says is exactly the value that *doesn't* survive a reinstall, the one
  property the whole mechanism exists for. A genuine trade-off between two real bugs, not a quick fix;
  needs a deliberate look at what fingerprint source actually satisfies both constraints.
- A handful of lower-severity items: one provisioning-script action (`mail-log-read`) whose `|| true`
  now swallows real errors alongside "no match," not just the latter; `SubdomainService::create()`
  compensating for one of its two failure points but not the other; two N+1 queries in Deploy from Git's
  history view and the Domains index. All noted, none urgent enough to bundle into today's already large
  set of live fixes.

## Verified

Full local suite (1,701 tests, up from 1,693 going in) and `pint --test` green after every fix. The two
provisioning-script fixes hand-verified against real input, since this script has no automated test
harness of its own.
